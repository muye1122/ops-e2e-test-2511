【详细方案】
Understanding: The buyer needs a runnable proof that generated operations content can be produced, reviewed, made effective and exported while nothing sensitive reaches the model vendor and no outbound channel is used. The deliverable is an executable acceptance suite plus the services it exercises, not a production platform. Every record, contact detail and paragraph in the demo is fictional.

Service topology: The operations assistant on port 3001 owns orchestration and the only egress gate. The model gateway on port 3002 forwards inference to the mock vendor on port 3004 and logs its own outbound call. The review queue on port 3003 stores drafts with pending_review/effective transitions and enforces that an L2 item cannot be approved by its own drafter (SELF_APPROVAL_FORBIDDEN). PostgreSQL 16 and Redis are declared in Compose as production replacement points; the delivered data layer is intentionally in-memory, and README states this boundary plainly.

Group 1 - activity plan: generation calls the gateway and writes a pending_review draft; an employee confirm transition makes it effective; a Word export endpoint then returns HTTP 200 with an application/msword payload. The test asserts the whole sequence and the exported title.

Group 2 - four channel copies: wechat, sms, email and in_app are all created at L2. The suite submits self-approval for each one and expects 403 with SELF_APPROVAL_FORBIDDEN, then approves each as a supervisor and asserts that all four rows in the queue are effective with the supervisor recorded as approver.

Group 3 - meeting summary: minutes containing a fictional mobile number, a fictional e-mail address and a line marked as non-public are split into segments and summarized through the gateway. Redaction runs before the first gateway call: phone and e-mail become [PHONE_n]/[EMAIL_n] placeholders and the whole non-public line becomes [PRIVATE_n]. The merged L1 summary is self-approved and becomes effective. A subsequent L2 retro draft is generated from the redacted body only; the reversible map restores phone and e-mail in the stored draft but never restores PRIVATE. Two separate tests read the vendor JSONL log from disk and through its API, asserting no raw number, address or non-public text appears, while two more tests assert those values are restored in the draft and the non-public paragraph appears nowhere.

Group 4 - zero outbound: every service exposes /audit/outbound. The suite aggregates all four logs after executing every flow, asserts that the operations assistant contacted exactly model-gateway and review-queue, that the gateway only contacted the mock vendor, and that blocked and send_calls arrays are empty everywhere. A pure evaluation endpoint demonstrates that an external or send-type URL is refused without creating a request or polluting the audit log.

Packaging and evidence: Playwright launches all services automatically with channel msedge and no browser download. One command (npm test) runs all checks; the workflow repeats it in CI, prints a case-by-case result matrix from the JSON report, and independently greps the vendor log for the fictional contact details, failing the build on any hit. README records the exact command and a real sample output; a verification note records real terminal output and the acceptance mapping. All third-party components are pinned by a lockfile; no new software is installed beyond the stated stack.

Acceptance and commercial terms: The quote covers the four runnable services, the eight-check suite, the demo UI, Docker Compose, CI workflow, README, result matrix and verification note, with 2 revision rounds, delivered in 3 weeks. Excluded are real model credentials, real database administration, real authentication, real messaging services, real business data and other products outside this scope.
